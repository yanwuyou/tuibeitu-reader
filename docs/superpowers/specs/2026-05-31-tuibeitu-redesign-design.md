# 推背图浏览器明显改版设计文档

## 背景

当前项目已经能以单文件 HTML 方式浏览《推背图》六十象，包含原文、金圣叹批注、白话解读、朝代时间线和基础翻页。它的问题不在于不能用，而是还停留在“文本翻页器”：视觉层次较初版，搜索和目录能力弱，内容说明和字词注解不足，难以让对《推背图》感兴趣的人快速进入阅读、考据和探索状态。

本次改版目标是在保留“一个 HTML 直接打开”的前提下，把页面升级为一个有审美、有注释、有脉络的《推背图》阅读工作台。

## 设计目标

1. 感官上：从普通古风卡片升级为成熟的文献阅读器气质。
2. 功能上：让用户可以按历史、关键词、象序、阅读路径快速进入内容。
3. 内容上：区分原文、金批、白话和解释性说明，增加生僻字注音与注解。
4. 技术上：保持单文件、零依赖、可双击打开，不引入构建工具和服务端。

## 明确不做

- 不做账号、云同步、在线数据库或服务端搜索。
- 不引入自动拼音库。自动注音容易误判多音字，本轮采用人工维护的高价值词表。
- 不做“预测准确率”“真假排行”等猎奇功能。
- 不大规模重写六十象正文内容，只在展示层和注释层增强。

## 推荐方案

采用“沉浸式阅读浏览器”方案：桌面端三栏布局，移动端单栏折叠。

- 左侧：目录、搜索、朝代筛选、探索入口。
- 中央：当前象正文，包括谶曰、颂曰、金圣叹批。
- 右侧：白话解读、看懂这一象、关键词、生僻字注解、内容说明。

这个方案比保守 polish 更能体现明显改版，又比专题资料站更适合单文件项目。

## 信息架构

### 顶部区域

顶部保留简洁品牌栏：

- 标题：推背图浏览器
- 副标题：六十象原文、金批、白话与字词注解
- 工具按钮：随机一象、继续阅读、全部目录

顶部不做大面积 hero，避免像宣传页。首页第一屏应该直接进入可用的阅读工作台。

### 左侧目录栏

左侧承担“进入内容”的任务：

- 搜索框：支持搜索象序、干支、标题、朝代、原文、金批、白话和注释词。
- 朝代筛选：总纲、唐、五代、宋、元、明、清、近现代、未来。
- 六十象目录：显示象序、干支、标题、朝代标签。
- 探索入口：
  - 从唐朝开始
  - 看近现代三象
  - 只看未来象
  - 查看所有带注音的字词
  - 随机一象

搜索和筛选同时作用于目录。无结果时显示简短空状态，不做复杂推荐。

### 中央正文区

中央是主要阅读区，默认展示完整原文结构：

- 当前象标题：第 X 象、干支、标题、朝代。
- 谶曰：保留原文换行，支持生僻字注音标记。
- 颂曰：保留原文换行，支持生僻字注音标记。
- 金圣叹批：作为批注原文展示，支持折叠。

现有 tab 会取消，改为默认展开的段落区。原因是《推背图》读者通常需要对照谶、颂、金批，隐藏式 tab 会割裂上下文。

### 右侧解读区

右侧帮助用户“看懂这一象”：

- 看懂这一象：从现有白话解读中提炼一段短摘要。
- 白话解读：展示完整解释文本。
- 关键词：从数据和注释词表中显示重要词。
- 字词注解：列出当前象出现的生僻字、典故词和拼音。
- 内容说明：明确“原文”“金批”“AI 白话解读”的来源和性质。

未来象与争议解释需要标记为解释性文本，不作事实断言。

## 生僻字注音与注解

新增内置 `GLOSSARY` 词表。词表以人工维护为准，字段如下：

```js
{
  term: "谶",
  pinyin: "chen4",
  displayPinyin: "chèn",
  meaning: "预言、隐语。",
  note: "在《推背图》中通常指带有象征和隐语性质的预言短句。"
}
```

首批词表覆盖高频且影响理解的字词，例如：

- 谶、颂、牝、阙、讴、讖、乾坤、干戈、赤羽、白头翁、金批、甲子、癸亥、阴阳、天数。

正文渲染时扫描词表命中项，用轻量标记包裹：

- 桌面端：悬停显示拼音和解释。
- 移动端：点击标记，在注解区定位对应解释。

为了保持简单，不实现复杂分词。优先按词表从长到短匹配，避免“乾坤”被拆成单字。

## 交互行为

### 导航

- 上一象、下一象按钮保留。
- 键盘左右方向键保留。
- URL hash 直达保留，例如 `#39`。
- 切换象时更新 hash、目录高亮和阅读进度。

### 搜索

搜索输入即时过滤目录。匹配范围：

- `id`
- `ganZhi`
- `title`
- `period`
- `chen`
- `song`
- `jinPi`
- `baiHua`
- `GLOSSARY.term`

搜索命中后点击结果进入对应象。搜索不高亮全文命中，避免实现复杂度膨胀。

### 阅读记忆

使用 `localStorage` 记住：

- 最近阅读象序。
- 是否打开右侧解读区。
- 最近使用的朝代筛选。

下次打开时显示“继续读第 X 象”入口。若本地存储不可用，页面仍正常工作。

### 随机一象

随机按钮跳转到 1-60 中任一象。若随机到当前象，可再取一次，避免看起来没有响应。

## 视觉设计

整体气质：文献阅读器，而不是装饰性古风页面。

配色建议：

- 背景：墨黑或深石色。
- 主纸面：宣纸白。
- 重点色：朱砂红。
- 辅助色：青铜绿或暗金。
- 正文：深墨色。

布局原则：

- 桌面端三栏稳定布局，左栏和右栏宽度固定，中间正文弹性扩展。
- 卡片圆角不超过 8px。
- 避免大面积渐变、装饰球、过重阴影。
- 字体层级清楚，正文行高适合中文长文阅读。
- 移动端改为单栏，目录和解读区可折叠。

## 数据与代码结构

仍在 `tuibeitu.html` 内完成：

- `TUI_BEI_DATA`：保留现有六十象数据。
- `DYNASTIES`：保留朝代映射。
- `GLOSSARY`：新增注音注解词表。
- 状态变量：
  - `currentIndex`
  - `currentFilter`
  - `searchQuery`
  - `isInsightOpen`
- 渲染函数：
  - `renderShell()`
  - `renderDirectory()`
  - `renderArticle()`
  - `renderInsights()`
  - `renderGlossaryForCurrentImage()`
  - `renderAnnotatedText(text)`
- 行为函数：
  - `navigateTo(index)`
  - `applySearch(query)`
  - `setPeriodFilter(period)`
  - `randomImage()`
  - `savePreferences()`
  - `restorePreferences()`

不新增外部 JS 文件，避免破坏“单文件可打开”的核心优点。

## 错误处理

- 若 hash 不合法，回到最近阅读象；若没有最近阅读，回到第 1 象。
- 若搜索无结果，显示空状态。
- 若某象没有白话或金批，显示“暂无内容”，不抛出错误。
- 若 `localStorage` 不可用，静默降级。

## 验证标准

改版完成后需要验证：

1. 双击打开 `tuibeitu.html` 可正常显示。
2. `#1`、`#39`、`#60` 可直达。
3. 上一象、下一象和键盘左右键可用。
4. 搜索“唐”“甲子”“谶”“近现代”等能得到合理结果。
5. 朝代筛选能正确过滤目录。
6. 随机一象能跳转。
7. 生僻字注音标记能显示，注解区能列出当前象相关词。
8. 移动端宽度下页面不横向溢出，目录和正文不挤压。
9. 浏览器控制台无错误。

## 实施顺序

1. 重构页面骨架和 CSS 布局。
2. 改正文渲染为完整展开结构。
3. 增加目录、搜索、筛选和探索入口。
4. 增加 `GLOSSARY` 与注音注解渲染。
5. 增加阅读记忆和随机一象。
6. 做桌面端与移动端验证。

## 风险与取舍

- 词表匹配可能误伤同字异义。本轮通过小词表、长词优先和人工选词降低风险。
- 单文件体积会继续增大，但当前项目规模仍可接受。
- 视觉改版会大幅改动 `tuibeitu.html`，但不改变数据来源和部署方式。
- 不做复杂全文高亮，是为了保持实现可控和页面稳定。
